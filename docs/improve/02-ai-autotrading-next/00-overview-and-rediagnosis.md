# 00 · 总纲：机制齐备、纪律预设默认生效，为何仍在亏损

> **指针**：前作 [`docs/improve/01-ai-autotrading/`](../01-ai-autotrading/00-总纲与现状诊断.md) 已把根因编号 D-1~D-18 冻结，并在 `00-总纲与现状诊断.md:124-136` 维护实施状态看板。本集是它的续集：不重编 D 号，不另立第二份状态看板，本轮新命题一律用 `N-` 前缀。
>
> **读者与用途**：写给项目负责人与量化方对接人。读完这一篇，你应当能决定下一轮投多少人力、四条主线先做哪一条、以及什么读数出现时应当叫停。工程细节在 01~04 号。

**本篇结论先行**：AI 自动交易当前亏损的主因，是系统被放在了一个**单笔波动幅度覆盖不了一次往返成本**的周期上，而**约束它的那组阈值从来没有被标定过**。两条都有仓库内实测记录：`ai_auto/tradability.py:4-6` 用用户本机真实 K 线测出，BTC-USDT-SWAP 在 `balanced` 预设、市价口径下，1m 有 **98.6%**、5m 有 **65.0%** 的 K 线断面达不到门禁的分母要求，而 1m 正是启动弹窗周期下拉的第一项；`ai_auto/discipline_view.py:108-111` 进一步记录，最宽松的 `aggressive` 档（k=1.0）在同一批 1m K 线上仍有 **93.0%** 的否决率，源码在同一处写明「真正的补救是换时间级别」。与此同时，`ai_auto/discipline.py:36` 对那张正在生产路径上生效的冻结阈值表自评「**这些数字没有经过回测校准**」。**第一件该做的事**是把「这个标的在这个周期上到底值不值得做」变成启动前与运行中都能读到的一等结论，而不是继续在一个负期望的断面上调参。

请注意一处极易读反的事实：`config.py` 里那一整排 `ai_trade_*` 的**出厂默认值**中，每一道闸的总开关都停在关闭位，但实盘跑的不是它们。`config.py:538` 的 `ai_trade_discipline_enabled = True` 与 `config.py:539-540` 的 `ai_trade_discipline_default_preset = "balanced"`，让每一个从 API 层启动的会话都套上一份会话私有的 Settings 副本；`config.py:533-535` 逐字写明了这件事。用出厂默认值推断实盘行为，正是那段注释明文警告过的读法。

排序的依据是量级差。N-1 直接决定了 90% 以上的开仓意图会不会被执行，其余各条都在剩下那不到 10% 里争夺改善空间。把 N-2 排在 N-3 / N-4 之后，是因为在 89% 腿费缺失的样本上标定阈值，标出来的数不可证伪；先修口径，再谈标定。

N-1 的算术值得展开一句。门禁判据是 `毛 edge(bps) ≥ k_min × C(bps)`，分母 `C` 在默认成本断面上约 13 bps（taker 5 bps 双边、半价差回落 1 bps、冲击 0.5 bps，取值见 `config.py:449-452`），`balanced` 的 `k_min = 1.5` 于是要求毛 edge 达到约 19.5 bps。BTC 1m 上一根 K 线的 `1.0 × ATR(14)` 在 98.6% 的断面里达不到这个数（`tradability.py:4-6`）。同一条判据在 5m 上的未达标比例降到 65.0%，量级差就是这么来的。真实否决率还会比这两个数更高：探针的分子只取 ATR 一项，而门禁的分子还要再对单仓 OCO 止盈距离与信号先验 EV 取最小值（`tradability.py:24-27`），两项都只会让分子更小。

N-3 的算术同样干净。40% 的胜率要打平需要 1.47 的赔率，实测赔率约 1.01（`track_record.py:3-4`）。缺口 0.46 不可能靠调门禁阈值补上，它指向的是持有期、止盈距离与退出规则这一组结构参数。

## 三、目标与不做什么

**本轮目标**（三条，全部可判定）：

1. 让「这个标的在这个周期上值不值得做」成为启动前与运行中都能一眼读到的一等结论，并且这个结论可以被一个具体动作接住。
2. 让 `ai_auto/discipline.py` 冻结表里的每一个数字都有一份可复现的标定记录，说明它取自哪个实测读数、样本量多少、在什么条件下应当改。
3. 让任何一次阈值变更都必须附带一份可复现的闸门报告，报告不通过则变更不进主干。

**不做什么**：

- 不承诺任何收益率、年化或胜率数字。全集只允许出现门禁阈值与监控阈值，这条与前作 `00-总纲与现状诊断.md:54` 一致。
- 不重写既有确定性安全层（基础策略铁律、下单前反思、利润保护棘轮、回撤刹车），也不改动它们的极性。
- 不引入新的第三方 Python 依赖，计算侧只用 pandas / numpy 与仓库自实现指标。
- 不做高频与做市方向的改造。
- 不重新设计纪律档位。四档预设、逐字段覆盖、前端选择器与只读阈值表都已上线（`discipline.py:44`、`schemas.py:790-820`、`AiTradeLaunchModal.tsx:1105-1121`），本轮只在其上补标定、编排与回滚。
- 不动 D-9（反思层判据）与 D-11（铁律层性质）。两者都需要先有干净样本才谈得上改，属于 N-4 修完之后的下一轮。

三条目标各自的判定方式：目标一看首屏是否存在一个可点击的动作，把「该换周期」这句结论直接接到周期切换上；目标二看 `discipline.py` 冻结表的十六个键里有多少个能在文档中找到对应的标定记录，缺失的必须显式标注为「未标定」；目标三看主干上是否存在一次没有附闸门报告的 `ai_trade_*` 阈值变更，存在即目标三未达成。三条都不涉及收益数字，这是刻意的。

## 四、四条主线与阅读导航

**主线一 · 补证据**（[01 号](./01-evidence-layer.md)）。edge 门禁的分子与分母今天都建立在假设上：分母里的半价差恒等于配置常数，分子从不使用因子子系统已经算好的任何一个 IC。这条主线让两端都换成真实观测。它本身不改善盈利，但它决定了主线二标定出来的数是否可信。

**主线二 · 标定既有阈值并按序验证**（[02 号](./02-calibration-and-activation.md)）。四档预设已经在跑，缺的是三件东西：每个阈值的实测标定依据、单变量的调整顺序与观察窗口、自动回滚判据。这条主线的第一步是先按 N-1 判定这个周期值不值得调，确认值得之后才轮到动参数。

**主线三 · 建验证闭环**（[03 号](./03-verification-and-gates.md)）。回测的决策链已与实盘同构，纪律预设在两侧同源，但没有任何一份可复现的报告能支撑一次阈值变更。这条主线把同构性变成产物。

**主线四 · 产品化与还债**（[04 号](./04-product-and-robustness.md)）。把「我现在赚不赚钱」「为什么没开仓」「这个周期值不值得做」三个问题的答案收进同一屏，给既有档位的数字补上来历，并对九个超红线文件承诺不再恶化。

四条主线的依赖关系是串的：主线一为主线二提供可信的坐标系，主线三为主线二提供裁决权，主线四把前三条的产出交到用户手里。若人力只够做一件事，做主线四里的「首屏三问」加主线二里的「可交易性优先编排」，因为它们能让用户在亏掉更多钱之前停下来。

按人力估算，主线四的首屏改造与主线二的编排状态机是纯增量工作，落点集中且不触碰决策轮；主线一要新开一条 WS 订阅面，涉及连接压力与降级姿态，风险最高；主线三的闸门报告工作量中等但依赖主线一的成本口径。建议的推进顺序是主线四与主线二并行起步，主线一紧随，主线三收尾。这个顺序与 M4~M6 的编号并不完全一致，因为里程碑按「证据是否可信」分段，而排期按「谁挡住了谁」分段。

| 主线 | 落点性质 | 是否触碰决策轮 | 主要风险 |
|---|---|---|---|
| 一 · 补证据 | 新增两个模块 + 一条 WS 订阅面 | 是（成本装配） | 连接压力、prompt 膨胀 |
| 二 · 标定与编排 | 新增一个模块 + 一份 runbook | 否（只读计数与建议） | 编排结论可能是「怎么调都不行」 |
| 三 · 验证闭环 | 新增一个离线模块 | 否 | 闸门过严导致迭代停滞 |
| 四 · 产品化与还债 | 前端重排 + 后端已有读数的转发 | 否 | 首屏聚合造成误读 |

## 五、里程碑与出口条件

接续前作 M1~M3（见 `00-总纲与现状诊断.md:140-144`），本轮为 M4~M6。每个里程碑的出口条件都写成可判定的读数；哪一段是硬串行、哪一段可以并行，写在表下那一段里。

| 里程碑 | 主题 | 出口条件 | 采样窗口 | 不达标处置 |
|---|---|---|---|---|
| **M4 · 证据与口径** | 主线一 + N-4 口径修复 | ① 半价差实测占比 > 90%；② 腿费覆盖率（`feeTrips / roundTrips`）≥ 0.90；③ 成本模型与实测往返成本的中位偏差 < 5 bps | 滚动 100 笔往返 | 任一不达标即 M5 不启动。在腿费覆盖率达标前，任何阈值变更一律拒绝 |
| **M5 · 标定与单变量验证** | 主线二 + 主线三 | ① 每个被改动的阈值都有一份闸门报告；② 一轮编排完整走完并产出「调整前 / 调整后」对照；③ 池化净期望的 t 统计量绝对值 ≥ 2.0（复用 `config.py:564` 的 `ai_trade_profitability_t_threshold`）。这一格只判「能不能下结论」，不判「结论是好是坏」。**这组参数能不能进实盘另有一条判据**：体检卡结论码不是 `negative_significant`（冻结结论表见 `profitability.py:57-63`，判据在 `:178-179`）。结论码为该值时 M5 照样判为已完成，但它的结论是「这组参数不进实盘」，转入 §七 自我反驳给出的 N-3 路径，任何情况下都不得当作发版许可 | 池化样本 ≥ 30 笔（`config.py:563`） | t 值不达标即判「样本不足以支持任何阈值变更」，回到 M4 继续攒样本，**不得**继续调参 |
| **M6 · 产品化** | 主线四 | ① 首屏三问在三秒内可答，每问都指向一个具体动作；② 档位阈值表的每一行都能展开看到标定记录或明确的「未标定」标注；③ 超 800 行文件数不增，逐文件净增行数在硬上限内 | 每次发版 | 超红线文件数增加即阻断发版；标注缺失即视为 M6 未完成 |

硬串行只发生在 M4 与 M5 之间。M4 的三项出口条件全部是口径类读数，它们达标之前，M5 产出的任何标定值都无法被证伪，因此 M4 不达标即不批 M5 的任何一次阈值变更。M5 的第三项刻意复用了仓库已有的显著性参数（`ai_trade_profitability_min_trips = 30`、`ai_trade_profitability_t_threshold = 2.0`），避免为本轮另立一套判据。M4 的腿费覆盖率是个例外，它取 0.90 而不是复用仓库既有的 `ai_trade_track_record_min_fee_coverage = 0.5`（`config.py:570`）：那条 0.5 的线管的是「这一句成本文案能不能下发给模型」，本轮这条 0.90 管的是「这批往返能不能拿去标定一个真实资金上的阈值」，后者容不下 50% 的缺失率。两条线并存，不可互相替代。M6 可以与 M5 并行推进，因为首屏三问展示的是既有读数，不依赖任何新阈值。

一个必须提前说清的时间量级：M4 的「滚动 100 笔往返」在 1H 周期上按当前开仓频次可能需要数周。如果这个周期长到团队开始绕过出口条件，出口条件就失去了意义。可接受的加速方式只有一种，就是在多个标的上并行累积并按 `profitability.py:12-15` 的池化口径合并；缩短窗口或降低 t 阈值都不在允许范围内。

## 六、统一验收口径

复用前作 `00-总纲与现状诊断.md:9-17` 的符号体系（`E = p·W − (1−p)·L − C`、`k`、`f`），本轮新增五项指标。所有比例都必须与它自己的分母同屏出现，这是 `profitability.py:12-15` 已经写成硬约束的纪律。

| 指标 | 定义 | 阈值 | 采样窗口 | 不达标处置 |
|---|---|---|---|---|
| 闸门生效率 | 被 edge 门禁降级为观望的开仓意图数 / 开仓意图总数（分母取 `open_funnel` 的 `intents`） | 0.10 ~ 0.60 | 滚动 200 轮 | > 0.60 先按 N-1 复核周期，**不要**先放宽 k |
| 腿费覆盖率 | `feeTrips / roundTrips` | ≥ 0.90 | 滚动 100 笔 | 未达标前所有成本类读数标注为不可用 |
| 半价差实测占比 | 使用真实盘口算出的半价差轮次 / 总轮次 | > 0.90 | 滚动 200 轮 | 成本置信度保持 `degraded`，门禁按 `ai_trade_edge_gate_degraded_mult` 收紧（`config.py:458`） |
| 盈亏比缺口 | `breakevenPayoff − payoff`，两者由 `profitability.py:16-17` 成对产出 | ≤ 0 | 池化 ≥ 30 笔 | > 0 说明结构性不足，转入 N-3 的持有期与止盈距离复核 |
| 配置可达性 | 启动请求可直接改写的 `ai_trade_*` settings 键数 / 192（口径与本轮基线 8 见 [04 号 §一 缺口四](./04-product-and-robustness.md)） | 记录为准，逐轮上升 | 每次发版 | 下降即视为回归 |

数字的出处必须随数字一起写出。本篇里凡标注「源码记录」的读数（93.0%、98.6%、65.0%、62.3%、89.1%、40% 胜率、1.01 赔率）都来自仓库注释中已经落定的历史统计，它们的采集时间与样本量以各自源码处的记载为准，本轮没有重新测过。凡标注「本次实测」的读数（`ai_auto/` 的 75 个 `.py` 文件、192 个配置项、15 个超红线文件、11 张统计卡片、14 处 `<label>`）都是 2026-08-15 用 Python 逐行统计当前工作树得到的，口径写在各自出现的位置。这两类数字不可混用，也不可互相佐证。

## 七、风险与自我反驳

**风险一：把阈值往严调会撞上「永不开仓」。** 这不是理论风险，仓库已有四次前科并逐条写进注释：`discipline.py:30` 的共识门槛恒真、`edge_gate.py:11-13` 记录的「反思致永不开单」事故、`drawdown_brake.py:129-131` 的第二档锁存、`turnover_discipline.py:138-141` 的令牌桶容量。当前最宽松档已有 93.0% 否决率，可调余量比直觉小得多。回滚开关：`ai_trade_discipline_enabled=False`，优先级高于请求体（`config.py:536-538`），关闭即整轴不装配、逐字回退。

**风险二：在 89% 腿费缺失的样本上标定，等于把噪声固化成阈值。** 缓解办法写在 M4 的出口条件里：腿费覆盖率不到 0.90 之前，一次阈值变更都不批。代价是 M5 会被推迟，这个代价是刻意接受的。

**风险三：换到更长周期会让样本累积速度进一步下降。** 1H 相对 1m 的每日 K 线数少两个量级，开仓机会随之减少，而所有验收判据都要求滚动 30 到 100 笔往返。这条风险没有廉价的解法，只能靠多标的并行池化把样本速率补回来（`profitability.py:12-15` 的池化口径正是为此而设，且它已经明确禁止对比值求平均）。若并行之后仍然攒不够样本，正确动作是延长观察期而不是放宽判据。

**自我反驳（必须正面承认）**：如果本篇的核心结论成立，也就是主要矛盾在周期与标的的可交易性上，那么四条主线里有三条都不直接解决主要矛盾。主线一在补证据，主线二在标定一组可能根本不该在这个周期上生效的阈值，主线三在给一个负期望的断面建验证流程。为什么仍然要做？因为「换周期」这个决定本身需要被证伪。今天系统能给出的最强证据是一个窗口统计量（`tradability.py` 的否决率），它是一个**乐观下界**，源码在 `:24-27` 明确写着真实否决率只会更高。要把「换到 1H 之后就能赚钱」从一句猜测变成一个可验证的判断，需要主线一的干净成本口径、主线二的可比对照、主线三的闸门报告。三条主线是那个决定的前提条件。

**如果结论错了会怎样**：若在 1H 或 4H 上跑满 100 笔往返后净期望仍与 0 无法区分，那么正确结论是这套决策链在当前形态下不具备可证伪的 edge，此时应当停止加机制，转而做 N-3 指向的盈亏比结构问题（持有期、止盈距离、退出规则），而不是继续调门禁参数。

**本轮全部回滚开关一览**（提案实现时必须逐条备齐，缺一即视为该提案未完成）：

| 提案 | 总闸 | 关闭后的行为 |
|---|---|---|
| 微观结构接入（01 §二） | 新增总闸，默认关 | 半价差回落到 `ai_trade_half_spread_fallback_bps`，成本置信度保持 `degraded` |
| 因子证据接入（01 §三） | 新增总闸，默认关 | 快照整键缺席，prompt 逐字节回退 |
| 调整编排状态机（02 §五） | 新增总闸，默认关 | 不产出任何建议，阈值恒取会话启动时的预设 |
| 自动回滚（02 §四） | 复用 `ai_trade_discipline_enabled` | 整轴不装配，等价 `off` |
| 闸门报告（03） | 无需总闸（离线工具） | 关闭即回到当前的无报告状态 |
| 首屏三问（04 §三） | 无需总闸（纯展示） | 卡片不渲染，读数仍在 wire 上 |
