# 00 · 总纲与现状诊断

**本篇结论先行**：AI 自动交易实盘持续亏损，主因不是某个缺陷，而是整条链路优化的目标函数里**没有成本这一项**——实盘已实现盈亏至今是毛口径（`services/quant/app/live_auto/executor.py:779` 把每条成交的 `"fee"` 硬编码为 `0.0`），成本既不进盈亏、也不进任何门禁。**改什么**：把系统从叙事驱动（narrative-driven）改造成期望值驱动（EV-driven）。**为什么**：单笔净期望 `E = p·W − (1−p)·L − C` 中的 C 在实盘世界恒等于零，系统在一个系统性乐观的反馈里学习与决策。**验收看什么**：先看「费率入账完整性」是否到 100%，在它到 100% 之前，本文档集其余一切盈利能力指标都建立在被污染的标签上。

## 一、问题定位

### 1.1 统一符号体系（全集复用，禁止另立）

| 符号 | 含义 | 单位 | 由谁定义 |
|---|---|---|---|
| `p` | 单笔交易的胜率先验 | 概率 | [02 · 信号层](./02-信号层重构与元标签.md) |
| `W` / `L` | 单笔平均盈利 / 平均亏损幅度 | bps | [05 · 风险与仓位](./05-风险与仓位管理.md) |
| `C` | 往返交易成本（双腿费率 + 半价差 + 冲击 + 资金费率） | bps | [01 · 交易成本](./01-交易成本与执行质量.md) |
| `k` | 最小可交易 edge 倍数，门禁判据 `毛 edge ≥ k × C` | 无量纲 | 01，默认 `k_min = 2.0` |
| `f` | 最终下单仓位占比 | 比例 | 05，经既有 `quantize_size_fraction` 吸附 |

归因恒等式：`E = p·W − (1−p)·L − C`。本仓库所有确定性层（基础策略铁律、下单前反思、利润保护棘轮）解决的都是等式左侧「少犯错」，**没有任何一层回答「这笔交易的期望收益是否覆盖成本」**。

### 1.2 三条经回读源码确认的事实

1. **实盘已实现盈亏是毛口径。** `_close_pnl` 是纯价差乘数量（`services/quant/app/live_auto/executor.py:732-738`），成交记录写死 `"fee": 0.0`（`executor.py:779`），而 `session_pnl_usd = 已实现 + 未实现`（`executor.py:147-149`）正由它累加。会话级止盈止损（`services/quant/app/ai_auto/session.py:898-907`）、利润保护判据、统计看板与喂给模型的「会话盈亏」全部读这个值。
2. **`default_taker_fee_bps = 5.0` / `default_slippage_bps = 2.0`（`services/quant/app/config.py:280-281`）只服务于模拟。** 其消费方是 `SimBroker`（`services/quant/app/engine/simulator.py:103-109`）、AI 回测（`services/quant/app/ai_auto/backtest.py:248-249`）与纸面/影子路径（`services/quant/app/paper/session.py:60-61`、`ai_auto/signals.py:30-31`）。`LiveExecutor` 全链路从不引用它们。
3. **限价（maker）能力早已上线且默认开启。** `ai_trade_limit_orders_enabled` 默认 `True`（`config.py:163`），`_do_open` 按决策是否携带限价发出 `limit` 或 `market`（`executor.py:260-263`），背后有完整挂单状态机 `live_auto/resting.py` 与 `ai_trade_limit_order_ttl_s = 300.0`（`config.py:169`）。缺的不是能力，是挂价策略与费率归属记账。

## 二、目标与不做什么

**目标**：① 让实盘盈亏与决策条件共用同一套净额成本口径；② 给每笔候选交易一个可证伪的期望收益估计，让 `C`、`p`、波动率、体制、相关性进入同一个不等式；③ 把仓库里已有但与 AI 决策割裂的资产（因子 IC/RankIC、权重模型、`signal_edge` 事件研究、walk-forward）接进闭环。

**不做什么**：① 不承诺任何收益率、胜率或年化数字，全集只允许出现门禁阈值与监控阈值；② 不重写既有确定性安全层（铁律、反思、利润保护棘轮），只在其链条上新增一道；③ 不在本阶段更换模型供应商或引入新的第三方 Python 包（`services/quant/requirements.txt` 的计算侧只有 pandas/numpy，无 scikit-learn 等机器学习库）；④ 不做高频与做市方向的改造。

## 三、方案设计

**主线 A —— 成本先行。** 分两步且顺序不可颠倒：**A0** 先把成本记进账（修 D-16，让实盘盈亏变净额）；**A1** 再引入最小 edge 门禁 `毛 edge(bps) ≥ k_min × C(bps)`，`k_min` 默认 `2.0`。理由：门禁的分母与验收的分子若来自两套账，门禁调得再准也无法被证伪。

**主线 B —— 概率化而非叙事化。** 信号板现在给模型的是 `stance / latestSignal / strength / reason` 四元组（`signals.py:38-44`），全是立场、没有「这个立场历史上值多少钱」。改造后每条信号附带先验 `{winRate, meanRetBps, sampleN, ir, costBasis}`，共识从等权投票改为按 IR 加权的对数几率聚合。

**主线 C —— 离线闸门与在线闭环。** 任何参数变更先过五道闸（闸 0 链路同构性对账 → 闸 1 purged walk-forward 净收益 → 闸 2 成本敏感性 → 闸 3 决策重放 → 闸 4 纸面灰度），上线后由归因表持续度量四类偏差，超阈自动降级为只平不开。

**三阶段路线图**（细节见 [08 · 实施路线图](./08-实施路线图与里程碑.md)）：

| 阶段 | 主题 | 核心交付 | 出口条件 |
|---|---|---|---|
| 一 · 止血 | 成本记账 + 最小 edge 门禁 | A0 净额 PnL、成本模型、`apply_edge_gate` | 费率入账完整性 = 100%，决策转化率落回 10%~35% |
| 二 · 结构 | 概率化信号 + 因子接入 + 仓位重构 | 信号先验、`factorSnapshot`、波动率目标化仓位 | 闸 0~闸 3 全通过，滚动 100 笔净期望 > 0 |
| 三 · 进化 | 元标签、校准、组合风险预算 | 元模型、置信度校准、相关性约束 | 校准误差与漂移指标连续 4 周达标 |

## 五、验收指标与门禁

| 指标 | 定义 | 阈值 | 采样窗口 | 不达标处置 |
|---|---|---|---|---|
| 费率入账完整性 | 平仓笔中 `fee != 0` 的占比 | = 100%（当前 0%） | 滚动 50 笔 | **未达标前本表其余指标一律不得用于判断盈利能力** |
| 实测往返成本 | `feeOpen + feeClose + 2×slip + funding` 的中位数 | 记录为准，用于标定 `k_min` | 滚动 100 笔 | 与模型偏差 > 5 bps ⇒ 重估成本模型 |
| 净期望 / 笔 | `Σ净盈亏 / 往返笔数` | > 0 且 > 1×C | 滚动 100 笔 | 自动降级为只平不开 |
| 成本占比 | `Σ成本 / Σ毛盈亏绝对值` | < 35% | 滚动 100 笔 | 触发 01 执行改造复审 |
| 决策转化率 | 产生成交的轮次 / 决策轮次 | 10%~35% | 滚动 200 轮 | 复审 04 频率治理参数 |
| 置信度校准误差 | 预测胜率分箱的 Brier 分数 | < 0.24 | 滚动 100 笔 | 关闭以置信度为输入的仓位放大 |
| 回测-实盘漂移 | 同期动作分布的 JS 散度 | < 0.15 | 每周 | 暂停参数变更，回到闸门 |
| 最大回撤 | 会话权益峰谷比 | < 预算的 15% | 实时 | 触发回撤刹车，当日停开新仓 |

## 六、风险与回滚

**自我反驳**：本计划的核心假设是「亏损来自负期望而非运气」。若 A0 落地后滚动 100 笔的净期望在统计上与 0 无法区分（t 值绝对值 < 1.0），则真正的结论是**样本量不足以支持任何改造决策**，此时继续叠加门禁只会把系统调成永不开仓——本仓库有过「反思致永不开单」的同类事故。因此阶段一的出口条件里必须同时监控「决策转化率下限 10%」，跌破即视为过度收紧并回滚。

**风险与回滚开关**：① A0 是破坏性变更，切换后用户会看到「同样行情、盈亏数字变差」，必须提供独立开关且**默认关闭 ⇒ 逐字回退毛口径**，并给出历史数据不可比声明；② edge 门禁与先验成本口径叠加可能造成双重计费导致开仓率骤降为 0，监控信号是「连续 200 轮零开仓」，回滚动作是把 `k_min` 置 0 等价于关闭该层；③ 一次提出过多机制会让计划变成书架文档，缓解是 08 号强制三阶段切分，且阶段一只做 A0 与 edge 门禁两件事。
