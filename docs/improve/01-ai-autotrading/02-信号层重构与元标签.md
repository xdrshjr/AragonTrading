# 02 · 信号层重构与元标签

**本篇结论先行**：**改什么**：把信号板从「立场」升级为「带统计先验的概率」，并新增一层元标签（meta-labeling）模型，只回答「这一笔该不该做、做多大」，不回答方向。**为什么**：现在喂给模型的 `stance / latestSignal / strength / reason` 四元组（`services/quant/app/ai_auto/signals.py:38-44`）全是立场，没有任何一条告诉模型「这个立场历史上值多少钱」；共识又是等权投票（`signals.py:59`），已失效策略与高 IC 策略同权。**验收看什么**：先验样本量与显著性达标率、加权共识相对等权共识的净期望增量、以及「双重计费导致永不开仓」这条回滚触发条件。

> **实施状态**：D-5 见 [00 · 七、实施状态看板](./00-总纲与现状诊断.md#七实施状态看板由实现节点维护单一真源)；设计文档 [`docs/plans/ai-trade-signal-prior-and-ev-gate/spec.md`](../../plans/ai-trade-signal-prior-and-ev-gate/spec.md)。

## 一、问题定位

**D-5（无质量先验、共识等权）**：`StrategySignalView`（`signals.py:35-44`）的字段是 `strategy_id / name / stance / latest_signal / strength / reason / risk_params`，没有一个字段承载历史统计。`compute_consensus`（`signals.py:59`）把多空票数简单相加，`apply_consensus_gate`（`signals.py:137`）据此按 `ai_trade_min_consensus`（默认 `0`，即关闭，`services/quant/app/config.py:145`）放行。结果是：一个连续三个月失效的策略，与一个 IC 显著为正的策略，在共识里贡献完全相同的一票。

**D-7（置信度未校准）**：`ai_trade_min_confidence` 默认 `0.0`（`config.py:128`），门槛形同虚设；`_compute_ai_stats` 只统计 `avgConfidence`（`services/quant/app/ai_auto/session.py:1398`），从不与实际胜率对照。也就是说模型自报的置信度**从未被证伪过**，因此不能用作仓位或门禁的输入。

**D-15（缺显著性口径）**：`_compute_ai_stats`（`session.py:1357-1404`）产出的是动作计数、观望占比、平均置信度、降级数与四个反思计数，没有任何净期望、t 值或成本占比。缺了这层，「亏损是运气还是负期望」无法回答。

**这构成一条因果链**：无先验 ⇒ 共识等权 ⇒ 模型只能靠叙事权衡 ⇒ 笔笔都做 ⇒ 成本吃光微弱 edge。元标签正好对症这条链的最后一环——方向判断也许尚可，但「笔笔都做」必然亏。

## 二、目标与不做什么

**目标**：① 给每条信号/策略附一个可证伪的先验 `p`；② 共识从等权投票升级为按信息比率（IR）加权的对数几率聚合；③ 新增元标签模型输出 `pWin` 与 `expectedEdgeBps`，供 [01](./01-交易成本与执行质量.md) 的 edge 门禁与 [05](./05-风险与仓位管理.md) 的仓位公式消费。

**不做什么**：① **不改 `compute_consensus`**——它的等权口径有既有回归断言守着，新增并列函数而非原地修改；② 不让元模型决定方向，它只做二分类的「做/不做」；③ **不假定 scikit-learn 可用**——`services/quant/requirements.txt` 的计算侧只有 pandas/numpy，无 scikit-learn；④ 不在决策轮内做任何训练或数据库 IO。

## 三、方案设计

### 3.1 先验的两路来源（必须写成两路）

仓库的 `engine/signal_edge.py` 只覆盖 **8 个内置信号检测器**（`services/quant/app/engine/signal_edge.py:50-107`：量能突破/破位、RSI 超卖/超买、布林上下轨触碰、EMA 金叉/死叉），其键是**信号名**而非 `strategyId`，因此**无法**直接产出按策略归集的先验。两路来源分工如下：

| 来源 | 覆盖对象 | 实现路径 | 归集键 |
|---|---|---|---|
| `signal_edge` 事件研究 | 8 个内置信号 | `signal_edge.forward_returns`（`signal_edge.py:265`） | `signalKey` |
| 策略离线重放 | 用户策略库中的每个策略 | `engine/backtester.run_backtest`（`engine/backtester.py:66`）+ `SimBroker` 按 `(instId, bar, regime)` 重放 | `strategyId` |
| 因子侧证据 | 单因子与组合因子 | `engine/factors/evaluation.evaluate_factor`（`engine/factors/evaluation.py:201`） | `factorKey`，详见 [03](./03-因子层接入AI决策.md) |

三路均在 purged walk-forward 切分上计算并落库，在线只读快照。样本量底线继承既有约定：`MIN_IC_SEGMENTS = 6`（`evaluation.py:21`），有效段数不足即不输出 t 值，先验同样标记为不可用。

### 3.2 成本口径去重（必填字段，防永不开仓）

`signal_edge._summarize_horizon` 已内建 `cost_bps` 参数并产出 `netMeanRet`（`signal_edge.py:241,262`）；影子 broker 也已按 5 / 2 bps 计费（`signals.py:30-31,85-86`）。因此**每条先验必须显式记录自己的成本口径**：`costBasis ∈ {"gross", "net@Nbps"}`。[04](./04-决策智能体改造.md) 组装 EV 不等式时按该字段决定是否再扣一次成本。**这不是洁癖**：若先验已是净值而 01 号又扣一次，edge 恒为负，系统会退化成永不开仓——本仓库有过同类事故。

### 3.3 元标签模型（新增纯 numpy 模块）

**实现前提必须写清楚**：`engine/factors/tree_ensemble.py` 只导出 `fit_rf_importances` / `fit_gbdt_importances` / `fit_extra_trees_importances`（`services/quant/app/engine/factors/tree_ensemble.py:234,270,305`），返回的是**特征重要度向量**，既无分类器、无概率输出，也无模型持久化。因此元模型是**新增模块** `engine/factors/meta_label.py`（约 260 行），仅复用该文件的分裂原语 `_build_tree` / `_predict_tree`（`tree_ensemble.py:196,220`）、`BUILTIN_SEED = 0`（`tree_ensemble.py:40`）与 `BUILTIN_MAX_TRAIN_ROWS = 4000` 的行数封顶（`tree_ensemble.py:39`）。

**降级链（三级，逐级更保守）**：树模型 → 校准 logistic（同样纯 numpy，样本不足或树训练退化时启用）→ **整键缺席**（回退到无元标签的既有行为，prompt 逐字回退）。

**标签用 triple-barrier**（上轨 / 下轨 / 时间轨），轨宽由 ATR 定标，复用 `engine/indicators.atr`（`services/quant/app/engine/indicators.py:48`），周期与 `ai_trade_profit_guard_atr_period = 14`（`config.py:242`）同源，且与 [05](./05-风险与仓位管理.md) 的自适应止损共用同一套 ATR 口径。

| 参数 | 默认值 | 取值依据 |
|---|---|---|
| `meta_label_min_samples` | 200 | 低于此样本量二分类概率不可信，直接降级为 logistic |
| `meta_label_min_prob` | 0.55 | 与 `k_min = 2.0` 配套：p=0.55、盈亏比 1:1 时毛 edge 才勉强覆盖 2 倍成本 |
| `triple_barrier_atr_mult` | 2.0 | 与利润保护的 ATR 上界 3.0 / 下界 0.8（`config.py:243-244`）同区间，取中值 |
| `triple_barrier_max_bars` | 24 | 时间轨；15m 周期约 6 小时，覆盖一个资金费率结算周期的多数情形 |
| `prior_decay_half_life_days` | 30 | 加密市场体制切换快，30 天半衰期让三个月前的样本权重降到约 1/8 |

### 3.4 加权共识

新增并列函数 `compute_weighted_consensus`，按每条信号先验的 IR 做对数几率聚合：`logit_total = Σ wᵢ · logit(pᵢ)`，`wᵢ = clamp(IRᵢ, 0, 2)`。**保留原等权票数字段向后兼容**，加权结果作为新增键下发；未装配先验时该键整体缺席，`compute_consensus` 的行为逐字不变。

## 五、验收指标与门禁

| 指标 | 阈值 | 采样窗口 | 不达标处置 |
|---|---|---|---|
| 先验覆盖率 | ≥ 80% 的在用策略/信号有可用先验 | 每次离线重算 | 未覆盖者按等权处理并在轨迹留痕 |
| 先验显著性达标率 | 有效段数 ≥ 6 的先验占比 ≥ 60% | 每次离线重算 | 拉长样本窗口或合并相邻 regime |
| 元模型校准误差 | 分箱 Brier 分数 < 0.24 | 滚动 100 笔 | 降级到 logistic；再不达标整键缺席 |
| 加权共识增量 | 相同期间净期望 ≥ 等权共识 | 滚动 200 轮离线重放 | 回退等权，保留先验仅作展示 |
| **零开仓监控** | 连续 200 轮 `open_*` 为 0 | 实时 | **立即判定为双重计费或过度收紧**，回滚开关见下节 |
| 先验陈旧度 | `asOfTs` 距今 < 7 天 | 每日 | 超期整键缺席，回退无先验行为 |

## 六、风险与回滚

**自我反驳一（必须写明）**：**双重计费会导致永不开仓。** 若先验的 `costBasis` 为 `net@14bps` 而 04 号又按 01 号成本扣一次，任何真实 edge 都会被判死。监控信号是上表的「零开仓监控」与「edge 门禁拦截率 > 70%」两条同时触发；回滚动作是把 `signal_prior_enabled` 置 `False`，先验整键缺席、EV 不等式退回只用 01 号成本的形态。

**自我反驳二**：**本改动可能反而降低收益。** 先验是对过去的统计，加密市场体制切换极快；在体制刚翻转的窗口里，高 IR 的历史策略恰恰是最容易失效的那个，加权共识会把错误放大——这比等权更危险。缓解是 `decay_half_life_days = 30` 的时间衰减 + 按 regime 分桶存储 + 「先验陈旧度」门禁；监控信号是加权共识与等权共识的动作分歧率，若分歧率 > 40% 且分歧轮的胜率低于同期整体胜率，立即回退等权。

**自我反驳三**：元标签本身可能只是在拟合噪声。样本量 200 对二分类而言是下限而非充裕；若滚动窗口内 `pWin` 的分布方差极小（近似常数），说明模型没学到东西，应直接整键缺席而不是保留一个假装有信息的常数。

**回滚开关**：`signal_prior_enabled`、`meta_label_enabled`、`weighted_consensus_enabled` 三个独立开关，**默认全部 `False` ⇒ 逐字回退当前行为**。上线前须过 [06](./06-离线评估与上线闸门.md) 的闸 1~闸 3。
