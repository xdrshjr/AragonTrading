# 04 · 决策智能体改造

**本篇结论先行**：**改什么**：把 prompt、决策工具 schema 与门禁链从「叙事驱动」改为「期望值驱动」——模型不再只回答「往哪边」，而必须回答「这笔的期望收益是否覆盖成本」；同时引入置信度校准与**条件性**频率治理。**为什么**：系统 prompt 的纪律 3 现在只写「风险优先……避免频繁反手与过度交易」（`services/quant/app/ai_auto/prompts.py:121-122`），全篇没有任何成本项或 EV 目标函数（D-8）；置信度门槛 `ai_trade_min_confidence` 默认 `0.0`（`services/quant/app/config.py:128`）形同虚设（D-7）；决策频率由墙钟与 K 线**双触发**结构性推高（D-10）。**验收看什么**：决策转化率是否落回 10%~35%、模型自估 edge 与门禁计算 edge 的一致性、以及置信度校准的 Brier 分数。

## 一、问题定位

**D-8（无 EV 目标函数）**：`build_ai_trade_system_prompt`（`prompts.py:70`）的宪章写得相当克制且完整——首要原则明确「信号是参考，不是指令」（`prompts.py:103-106`），纪律 1 要求分步研判（`prompts.py:109-115`），纪律 2 要求只用真实数据。**唯独没有一句话让模型把交易成本纳入判断**。模型因此无法区分「方向大概率对、但幅度不够付手续费」与「方向对且幅度够」这两种本质不同的情形。

**D-7（置信度未校准）**：门槛默认 `0.0`，且 `avgConfidence`（`services/quant/app/ai_auto/session.py:1398`）从不与实际胜率对照。一个从未被证伪的自报数值，既不能做门禁，也不能做仓位输入。

**D-9（反思层在两个极端之间摆动）**：`build_reflection_system_prompt` 的 docstring 明确记录了这段历史（`prompts.py:527-530`）：曾用「任何不放心即 abort（宁可错过不可做错）」，历史样本 7/7 全否决，是「永不开单」因果链的根因，遂改为分级复核标准（默认 confirm、收缩优先、abort 须指名实质性缺陷、机会成本对称，`prompts.py:538-547`）。**问题不在措辞，而在这一层始终没有统计阈值可依**——只能靠调温在两个极端之间找平衡。

**D-10（频率由双触发推高）**：墙钟唤醒默认 2 分钟（`ai_trade_wake_interval_default_min = 2.0`，`config.py:184`，硬下限 30 秒，`config.py:185`）与每根确认 K 线唤醒叠加。仓库已有一层去重守卫 `should_skip_interval_wake`（`services/quant/app/ai_auto/wake_guard.py`，在 `session.py:408-414` 调用），但它只在**空仓且数据未变**时跳过，**不是 EV 条件**。高频率 × 未验证 edge × 从不入账的成本 = 结构性负期望。

## 二、目标与不做什么

**目标**：① prompt 中显式给出 EV 不等式与成本口径，让模型的研判包含「值不值得做」这一步；② 决策工具 schema 增加三个**可选**字段，让模型自报期望 edge、失效价与预期持有根数，供服务端做一致性校验；③ 把频率治理做成条件性的——EV 不足才抑制，而非一律降频。

**不做什么**：① **不改 `required` 字段、不破坏零回归恒等断言**——`build_decision_tool_schema(0.0) is DECISION_TOOL_SCHEMA` 这条断言（`prompts.py:180-184` 注释，测试在 `test_ai_trade_position_step.py:132`）是所有新字段**必须默认 False 总闸**的硬约束来源；② 不信任模型自报的数值——服务端只用它做一致性校验；③ 不删除反思层，也不再靠调措辞找平衡；④ 不把「降低频率」当万灵药。

## 三、方案设计

### 3.1 prompt 的 EV 化改造（三处最小改动）

| 位置 | 现状 | 改造 |
|---|---|---|
| 纪律 3（`prompts.py:121-122`） | 「风险优先……避免频繁反手与过度交易」 | 追加：本轮往返成本约 `C` bps，只有当你判断的目标位距离减去止损距离的期望值 ≥ `k_min × C` 时才应开仓 |
| 研判步骤（`prompts.py:109-115` 的 ①~⑧） | 八步，末步为「结论」 | 在「结论」前插入一步：**成本与期望值核算**——写出目标位、失效价、预期持有根数与由此推出的毛 edge |
| 新增渲染段 | 无 | `_format_cost_context`：把 [01](./01-交易成本与执行质量.md) 的 `CostBreakdown` 渲染成一行中文，含 `confidence` 降级标注 |

三处都遵循「键缺失即整段省略、prompt 渲染逐字节回退」的既有范式：未装配成本模型时，纪律 3 与研判步骤逐字回退当前文案。

### 3.2 决策工具 schema 的增量（三个可选字段）

在 `submit_trade_decision` 的 `input_schema.properties` 上追加 `expectedEdgeBps`（模型自估毛 edge）、`invalidationPx`（失效价，方向性硬约束）、`horizonBars`（预期持有根数），**`required` 不变**。实现范式与既有 `holdExitPx` 完全一致（`prompts.py:210-214`）：由一个默认 `False` 的 keyword-only 总闸控制，只在调用方自己的 `props` 浅拷贝上补，**绝不就地改模块常量**。

**服务端不信任其数值**，只做两件事：① 一致性校验——模型自估 edge 与门禁计算的 edge 差异超过 `edge_consistency_tol_bps` 即降级为 hold 并留痕；② 把 `invalidationPx` 传给 [05](./05-风险与仓位管理.md) 作为止损位的候选输入之一。这与仓库既有的「schema 是软引导、服务端才是硬保证」姿态一致（`prompts.py:196-197`）。

### 3.3 门禁链与插入位置

现有确定性链：铁律（`session.py:571-572`）→ 利润保护冷却（`session.py:574`）→ 共识（`session.py:575`）→ 下单前反思（`session.py:578-579`）→ 执行（`session.py:580`）。**edge 门禁插在共识门禁之后、反思之前**，即 `session.py:575` 与 `session.py:578` 之间：① 必须落在 `decide` 之后，否则重试循环只认 `_map_decision` 的 degrade，落进去会每轮白烧 LLM；② 必须落在反思之前，被拦轮此时已是 `hold`，反思对 `hold` 本就直通（`session.py:644-646`）⇒ 自动省掉一次反思 LLM 调用。

### 3.4 置信度校准与条件性频率治理

置信度先做**观测**再做**门禁**：离线按分箱统计「模型自报置信度」对「实际胜率」的映射，产出一条单调校准曲线（isotonic 或分段线性，纯 numpy）。校准后的 `pCalibrated` 才允许进入仓位公式；未校准前 `ai_trade_min_confidence` 保持 `0.0` 不动。

频率治理**必须是条件性的**：不降低唤醒频率，而是把「EV 不足」的轮次在 edge 门禁处拦成 hold。这样机会仍被检视，只是不被交易。

| 参数 | 默认值 | 取值依据 |
|---|---|---|
| `edge_decision_fields_enabled` | `False` | 总闸；默认关 ⇒ schema 恒等断言原样通过 |
| `edge_consistency_tol_bps` | 15.0 | 约等于一个往返成本；差异超过一个成本量级说明模型与系统对同一笔的判断不在一个世界 |
| `k_min` | 2.0 | 与 [01](./01-交易成本与执行质量.md) 同源，全集唯一取值 |
| `confidence_calibration_min_samples` | 100 | 低于此样本量校准曲线不可信，保持恒等映射 |
| `min_horizon_bars` | 2 | 预期持有不足 2 根的交易在 15m 周期上几乎必然被成本吃掉 |

## 五、验收指标与门禁

| 指标 | 阈值 | 采样窗口 | 不达标处置 |
|---|---|---|---|
| 决策转化率 | 10%~35% | 滚动 200 轮 | 高于 35% 说明门禁未生效；低于 10% 判定过度收紧并回滚 |
| 模型-系统 edge 一致率 | 差异 < 15 bps 的轮次占比 ≥ 60% | 滚动 200 轮 | 低于阈值说明 prompt 未把成本口径讲清楚，回退成本渲染段重写 |
| 置信度校准误差 | Brier 分数 < 0.24 | 滚动 100 笔 | 关闭以置信度为输入的仓位放大 |
| 错失交易率 | 被 edge 门禁拦下但 `horizonBars` 内方向正确的比例 < 60% | 滚动 100 次拦截 | 超阈说明 `k_min` 过高，下调至 1.5 重测 |
| **零开仓监控** | 连续 200 轮 `open_*` 为 0 | 实时 | **立即回滚**：`k_min = 0` 等价关闭门禁 |
| schema 零回归 | `build_decision_tool_schema(0.0) is DECISION_TOOL_SCHEMA` 恒真 | 每次提交 | 阻断合并 |

## 六、风险与回滚

**自我反驳一（必须写明）**：**双重计费会导致永不开仓。** 若 [02](./02-信号层重构与元标签.md) 的先验 `costBasis` 已是 `net@Nbps`，而本篇的 EV 不等式又按 01 号成本扣一次，任何真实 edge 都会被判死，系统退化为永不开仓——本仓库有过「反思致永不开单」的同类事故，代价是整整一个迭代。**监控信号**：上表「零开仓监控」+ edge 门禁拦截率 > 70% 同时触发。**回滚开关**：`k_min = 0`（关门禁）与 `signal_prior_enabled = False`（关先验）两个独立开关，任一即可脱困。

**自我反驳二**：**本改动可能反而降低收益。** 让模型显式核算成本，可能诱导它系统性地高估目标位距离以「凑够」edge 门槛——这是把叙事从「方向」转移到「幅度」，而不是消除叙事。缓解：服务端的一致性校验用**门禁自己算的 edge** 而非模型自报值做判据，模型自报值只用于观测与留痕；监控信号是「模型自估 edge 的分布是否在门禁上线后整体右移」，若右移超过一个成本量级即判定为凑数行为。

**自我反驳三**：把频率治理做成条件性的，意味着唤醒次数不降、LLM 调用成本不降。若阶段一结束时 token 成本显著上升而净期望无改善，正确动作是**同时**上调 `ai_trade_wake_interval_default_min`（从 2.0 到 5.0）——但这必须是被数据逼出来的决定，不能是先验的「降频总是好的」。

**回滚路径**：`edge_decision_fields_enabled = False` ⇒ schema 与 prompt 逐字节回退；`k_min = 0` ⇒ 门禁空转；校准曲线未装配时恒等映射。三者独立。上线闸门见 [06](./06-离线评估与上线闸门.md)。
