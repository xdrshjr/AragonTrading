# 03 · 因子层接入 AI 决策

**本篇结论先行**：**改什么**：把仓库里已经建成、但与 AI 决策完全割裂的因子子系统（IC/RankIC 评估、权重模型、组合因子）经一个新的 `payload["factorSnapshot"]` 键接进决策上下文。**为什么**：`services/quant/app/ai_auto/market_digest.py:14` 的模块 docstring 明写「**不接入**重型 `engine/factors/*`」——模型现在看到的只是 RSI/MACD/布林/ATR 这几个模块级常量参数的读数，而仓库里那套带 IC、t 值、分位分层、权重训练的正交证据源，一行都没进决策。**验收看什么**：因子快照的装配率与降级率、前视偏差（look-ahead）自查是否 100% 通过、以及接入前后决策一致性的漂移幅度。

## 一、问题定位

**D-4（因子层与决策层割裂）**：`market_digest.build_market_digest`（`market_digest.py:45`）产出的是价格走势、成交量与五个技术读数（`_rsi_reading` / `_macd_reading` / `_boll_reading` / `_atr_reading` / `_roc_reading`，`market_digest.py:195-251`），全部是模块级常量参数下的**单点读数**，没有任何统计质量标注。与此同时，`engine/factors/evaluation.py:201` 的 `evaluate_factor` 已经能产出 IC、RankIC、IR、t 值与分位分层收益，`engine/factors/scoring.py:110-155` 的 `score_breakdown` / `compose_score` 已经能按权重合成组合因子分数——**这些成果在 AI 决策链路里的复用率是零**。

**这意味着两件事**：① 模型缺少正交证据源，只能在同一族技术指标内部反复权衡，容易把相关性极高的几个读数当成互相印证；② 仓库为因子挖掘、权重训练、非线性训练器投入的全部工程量，对实盘盈亏没有产生任何作用。

**顺带的口径风险**：`market_digest` 的 ATR 周期与 `ai_trade_profit_guard_atr_period = 14`（`services/quant/app/config.py:242`）是**同值但各自独立**的两份常量（`config.py:240-241` 的注释已明确记录这一决定）。因子接入后若再引入第三份 ATR 口径，三处漂移只是时间问题。

## 二、目标与不做什么

**目标**：① 在决策 payload 中新增 `factorSnapshot` 键，承载因子值、z 分数、IC/RankIC 与权重；② 让因子分数进入 [02](./02-信号层重构与元标签.md) 的先验体系与 [04](./04-决策智能体改造.md) 的 EV 不等式，而不是只做展示；③ 用契约字段把前视偏差挡在装配层。

**不做什么**：① **不改 `market_digest.py` 的既有产出**——它的轻量定位是对的，因子快照是并列的新键而非替换；② 不在决策轮内做因子挖掘或权重训练（全部离线，在线只读快照）；③ 不引入盘口/成交流等微观结构数据——那需要打开 `market_channels`（AI 会话当前构造的是 candle-only 包装器，`services/quant/app/ai_auto/session.py:275` → `services/quant/app/okx/ws_client.py:204`），属于 D-3 的独立议题，本篇只标注依赖不实施；④ 不新增数据库表。

## 三、方案设计

### 3.1 快照形状与装配时机

`factorSnapshot`（提案）在会话启动时加载一次模型元数据，在每根确认 K 线上重算因子值（纯计算，无 IO），随 payload 一起下发。形状：

> 提案（proposal）· 未实现

```text
{asOfTs, model{id, kind, trainedAt, normWindow},
 factors:[{key, cn, value, z, ic, rankIc, weight}], score, scorePct, regime}
```

`cn` 是中文名，用于 prompt 渲染时直接落中文（与仓库既有中文化展示范式一致）；`scorePct` 是分数在训练期分布中的百分位，比裸分数更可解释。

### 3.2 前视偏差的三道硬约束

| 约束 | 判据 | 不满足时的行为 |
|---|---|---|
| 时间对齐 | `asOfTs` 必须等于当前确认根的收盘时间戳 | 整键缺席 |
| 归一化契约一致 | 推理期 `normWindow` 必须等于训练期记录值 | 整键缺席 |
| 因果 z 分数 | 只允许 `causal_zscore`（`engine/factors/scoring.py:69`），禁止全样本标准化 | 整键缺席 |

`normWindow` 与 clip 的解析走既有单一真源 `resolve_norm_contract`（`scoring.py:48`），**不得另写一份**。三道约束任一不满足即整键缺席——沿用本仓库「键缺失即整段省略、prompt 渲染逐字节回退」的既有范式（`services/quant/app/ai_auto/prompts.py` 中 `_format_market_context`、`_format_base_rules`、`_format_profit_guard` 一致采用），保证任何降级路径都能零回归退化。

### 3.3 因子如何真正参与决策（而非只做展示）

三条用途，按落地难度递增：

1. **作为 prompt 证据**：新增 `_format_factor_snapshot` 渲染段，把 top-N 因子的中文名、z 分数与 IC 一并给模型，并显式标注「IC 是历史统计，不是当下保证」。默认 `factor_snapshot_top_n = 5`，依据是 prompt 现有各段的信息密度上限，超过 5 条会稀释注意力。
2. **作为先验证据源**：因子的 IC/t 值按 [02](./02-信号层重构与元标签.md) 的 `SignalPrior` 形状归集（`source = "factor"`，归集键 `factorKey`），样本量底线继承 `MIN_IC_SEGMENTS = 6`（`services/quant/app/engine/factors/evaluation.py:21`）。
3. **作为元模型特征**：组合因子分数 `score` 与各因子 z 分数进入 `engine/factors/meta_label.py` 的特征矩阵，这是因子层对盈亏产生作用的**主路径**——prompt 展示只是辅助。

| 参数 | 默认值 | 取值依据 |
|---|---|---|
| `factor_snapshot_enabled` | `False` | 总闸；默认关即字节级回退，沿用仓库既有约定 |
| `factor_snapshot_top_n` | 5 | prompt 单段信息密度上限，超过则稀释注意力 |
| `factor_snapshot_min_ic_abs` | 0.02 | 低于此绝对 IC 的因子不进 prompt，只进元模型特征 |
| `factor_snapshot_max_age_s` | 一根 K 线周期 | 超龄即整键缺席，防用上一根的因子解释这一根 |
| `factor_model_kind` | 沿用工作台在用模型 | 不新增模型类型，复用既有权重模型工件 |

### 3.4 与 regime 的耦合

因子的 IC 在趋势与震荡体制下差异极大。快照带 `regime` 字段，先验按 `(instId, bar, regime)` 分桶（与 02 号同一分桶键）。regime 取值沿用仓库既有的市场体制枚举，**不新造一套**。

## 四、与现有代码的接入点

**现状已有什么**：`evaluate_factor` / `evaluate_factor_key` 的完整评估（`evaluation.py:201,235`）、`aggregate_eval_results` 的多标的聚合（`evaluation.py:314`）、`causal_zscore` 与 `resolve_norm_contract`（`scoring.py:69,48`）、`score_breakdown` / `compose_score` 的组合因子合成（`scoring.py:110,155`）、权重模型工作台与非线性训练器、因子集与策略的 1:1 自动同步。**因子子系统是本仓库最完整的资产之一，本篇不新建任何评估能力，只做接入。**

**落地位置**：新增 `ai_auto/factor_snapshot.py`（约 150 行，纯函数装配 + 三道契约校验），`ai_auto/prompts.py` 新增一个 `_format_factor_snapshot` 渲染函数（与既有 `_format_*` 系列同构，约 15 行）。`ai_auto/session.py` 现 1404 行、已超 `CLAUDE.md` 的 800 行红线，**只允许调用新模块，不允许在其中新增装配逻辑**。

## 五、验收指标与门禁

| 指标 | 阈值 | 采样窗口 | 不达标处置 |
|---|---|---|---|
| 快照装配率 | ≥ 95% 的决策轮成功装配 | 滚动 200 轮 | 排查契约校验失败原因；持续不达标则关闭总闸 |
| 契约校验拦截率 | 归一化窗口不一致的拦截数 = 0 | 每次模型切换后 | 非零即说明训练/推理口径漂移，阻断上线 |
| 前视偏差自查 | 离线重放中「用未来数据」的断言 100% 通过 | 每次离线重算 | 阻断：不通过不得上线 |
| 因子先验显著性 | 进入 prompt 的因子 t 值绝对值 ≥ 2.0 | 每次离线重算 | 降级为只进元模型特征，不进 prompt |
| 决策漂移 | 接入前后同 payload 重放的动作一致率 ≥ 70% | 离线重放 200 轮 | 低于阈值说明因子喧宾夺主，收缩 `top_n` |
| 快照陈旧度 | `asOfTs` 与当前确认根一致 | 实时 | 整键缺席 |

## 六、风险与回滚

**自我反驳一（必须写明）**：**本改动可能反而降低收益。** 因子的 IC 是**横截面统计**，本质上刻画的是「在一篮子标的上排序的能力」，而 AI 自动交易是**单标的择时**。把横截面 IC 直接当作择时证据存在口径错配，可能给模型一个虚假的置信来源。缓解：因子先验必须按单标的时间序列重新统计（而非直接沿用横截面 IC），进入 prompt 的门槛提高到 t 值绝对值 ≥ 2.0；监控信号是「有因子快照轮」与「无因子快照轮」的净期望差，若前者显著更差，立即关闭总闸。

**自我反驳二**：前视偏差是这类接入最经典的翻车方式，且**回测阶段完全看不出来**——曲线会变得非常好看。三道契约约束是必要条件而非充分条件；真正的判据是纸面灰度（[06](./06-离线评估与上线闸门.md) 的闸 4）中因子快照轮的实测胜率是否与离线一致，偏差超过 10 个百分点即判定存在泄漏。

**自我反驳三**：因子层接入会显著增加 prompt 长度与每轮 token 成本，而 [04](./04-决策智能体改造.md) 的频率治理正在往相反方向使力。若接入后每轮成本上升但净期望无改善，正确动作是**只保留元模型特征路径、砍掉 prompt 展示路径**，而不是两边都留。

**回滚路径**：`factor_snapshot_enabled = False` ⇒ 整键缺席 ⇒ prompt 与 payload 逐字节回退到当前形态，零残留。因子快照与 [02](./02-信号层重构与元标签.md) 的先验、[05](./05-风险与仓位管理.md) 的仓位公式之间只有单向依赖，关闭本篇不影响其余各篇独立回滚。
