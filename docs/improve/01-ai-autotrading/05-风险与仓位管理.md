# 05 · 风险与仓位管理

> **实施状态**：D-6 / D-12 / D-13 见 [00 · 七、实施状态看板](./00-总纲与现状诊断.md#七实施状态看板由实现节点维护单一真源)；设计文档 [`docs/plans/ai-trade-vol-sizing-and-drawdown-brake/spec.md`](../../plans/ai-trade-vol-sizing-and-drawdown-brake/spec.md)。已实现的三条与本篇原文的三处偏离见该 spec §9.3，实施期发现的方案缺陷见该 spec §十四。

**本篇结论先行**：**改什么**：把仓位从「模型自由给出的占比」改为波动率目标化的确定性计算，把止损止盈从固定百分比改为 ATR 自适应，并补上仓库当前完全没有的两件东西——组合相关性预算与回撤刹车。**为什么**：现在下单量是 `强度 × 预算 × 杠杆` 的直接乘积（`services/quant/app/live_auto/executor.py:691-703`），风控是固定的 `sl=5% / tp=10%`（`services/quant/app/config.py:104-105`），不随波动率变化（D-6）；多标的只按 `allocation_pct` 切预算（`services/quant/app/live_auto/manager.py:239`），名义分散但实际同向叠加（D-12）；除会话级绝对金额阈值外没有任何回撤刹车（D-13）。**验收看什么**：仓位与实现波动率的相关性、被扫损率、组合有效敞口、以及最大回撤是否被刹车真正拦住。

## 一、问题定位

**D-6（仓位与风控都是固定量）**：`_compute_sz`（`executor.py:691-703`）的核心是 `target_notional = clamp(strength, 0, 1) × budget_usd × leverage`，其中 `strength` 直接来自模型的 `sizeFraction`（经 `quantize_size_fraction` 吸附到用户档位）。这意味着**仓位大小完全由叙事决定**：模型说 0.5 就是 0.5，与当下波动率、与这笔的胜率先验、与账户已有敞口都无关。风控侧同理，`ai_trade_default_sl_pct = 0.05` 与 `tp_pct = 0.10`（`config.py:104-105`）是常数——高波动时 5% 止损会被噪音随手扫掉，低波动时又宽到失去保护意义。

**D-12（无相关性约束）**：`_preflight_group` 按 `allocation_pct` 把总预算线性切分（`manager.py:239`），并按同一比例缩放会话级阈值（`manager.py:296-297`）。BTC / ETH / SOL 三个成员在预算表上看是分散的，但在同向行情里日内相关系数常在 0.8 以上，**实际敞口接近三倍单标的**，而系统对此毫无感知。

**D-13（无回撤刹车）**：唯一的止损机制是 `_maybe_session_exit`（`services/quant/app/ai_auto/session.py:898-907`）——累计盈亏跌破绝对金额阈值即停会话。它是**终局开关**而非**减速带**：在触发之前，连亏五笔与连亏一笔的系统行为完全相同，亏损可以一路持续到预算耗尽。

**注意一个已存在的强约束**：仓库已有完整的利润保护棘轮（`services/quant/app/ai_auto/profit_guard.py`，配置见 `config.py:217-253`），包含浮盈武装线、回吐比例阶梯、ATR 上下界归一、保本线、冷却期与承诺退出线棘轮。**本篇不重建这一层**，只与它共用 ATR 口径并在其之上补「开仓前」的缺口——保护层管的是已开仓之后。

## 二、目标与不做什么

**目标**：① 仓位由 `pWin`、edge、成本与实现波动率共同决定，模型的 `sizeFraction` 降级为「上限提议」；② 止损止盈由 ATR 定标，与利润保护层共用同一套 ATR 参数；③ 引入组合相关性预算与回撤刹车两道新护栏。

**不做什么**：① **不重建利润保护棘轮**——它已上线且默认开启；② 不改 `position_ladder` 单一真源（`services/quant/app/ai_auto/signals.py:199`）与 `quantize_size_fraction` 的吸附行为（`signals.py:218`），新公式的输出仍须经它吸附；③ 不动交易所侧 OCO 的既有行为；④ 不引入组合优化求解器——相关性约束用简单的有效敞口上限实现即可。

## 三、方案设计

### 3.1 波动率目标化仓位

`f = clamp( min(kelly_fraction × λ, vol_target / realized_vol), 0, f_max )`，随后经既有 `quantize_size_fraction` 吸附到用户档位；模型给出的 `sizeFraction` **只能把结果调小、不能调大**。

其中 `kelly_fraction = (p·b − (1−p)) / b`，`b = (edgeBps − costBps) / stopBps` 为净盈亏比；`p` 取 [02](./02-信号层重构与元标签.md) 的校准后先验，`costBps` 取 [01](./01-交易成本与执行质量.md) 的成本模型。

| 参数 | 默认值 | 取值依据 |
|---|---|---|
| `kelly_lambda` (λ) | 0.25 | 四分之一凯利；先验估计误差下全凯利的破产风险不可接受，1/4 是业界常用的保守档 |
| `vol_target` | 年化 20% | 加密永续 7×24 交易，一年约 35040 根 15m，按 `√` 时间折算每根约 0.11%；与常见波动区间相比属中性偏保守 |
| `f_max` | 沿用既有分组敞口上限 | 不新增红线，复用 AI 分组已有的预算与占比封顶 |
| `realized_vol_window` | 96 根 | 15m 周期即一整天；短于此对单根异动过敏，长于此跟不上体制切换 |
| `sizing_enabled` | `False` | 总闸；默认关 ⇒ 逐字回退当前 `_compute_sz` 行为 |

### 3.2 ATR 自适应止损止盈

`stop_distance = atr_mult × ATR(14)`，`take_distance = rr × stop_distance`。ATR 复用 `engine/indicators.atr`（`services/quant/app/engine/indicators.py:48`），周期与 `ai_trade_profit_guard_atr_period = 14`（`config.py:242`）同源；倍数区间对齐保护层已有的 `atr_floor_mult = 0.8` 与 `atr_cap_mult = 3.0`（`config.py:243-244`），**不新造第三套 ATR 口径**。

| 参数 | 默认值 | 取值依据 |
|---|---|---|
| `stop_atr_mult` | 1.5 | 落在保护层既有的 0.8~3.0 区间中段；小于 0.8 会被日内噪音扫掉 |
| `rr`（盈亏比） | 2.0 | 与 `k_min = 2.0` 呼应：胜率 40% 时 2:1 盈亏比才勉强覆盖两倍成本 |
| `invalidation_priority` | 模型优先 | 模型给出 `invalidationPx`（[04](./04-决策智能体改造.md)）且比 ATR 止损更近时取模型值——只允许更保守 |

### 3.3 组合相关性预算

对 AI 分组的多个成员，用滚动 `realized_vol_window` 根的收益率相关矩阵计算**有效敞口**：`effective_exposure = Σᵢ Σⱼ wᵢwⱼρᵢⱼ` 的平方根乘以总名义额。若有效敞口超过 `effective_exposure_cap`，按比例缩减各成员本轮的 `f`。

| 参数 | 默认值 | 取值依据 |
|---|---|---|
| `effective_exposure_cap` | 1.5 × 单标的满仓名义额 | 三成员全相关时等于把三倍敞口压回 1.5 倍，仍保留分散收益 |
| `correlation_min_samples` | 96 | 与 `realized_vol_window` 同源，样本不足时保守按 ρ=1 处理 |

**样本不足时按完全相关处理**，即最保守假设，绝不按 0 处理。

### 3.4 回撤刹车与连亏熔断

三级减速，全部作用于「开新仓」，**平仓与撤单永不被拦**：

| 触发条件 | 默认阈值 | 动作 |
|---|---|---|
| 会话权益从峰值回撤 | 预算的 8% | 仓位系数乘 0.5 |
| 会话权益从峰值回撤 | 预算的 15% | 当日只平不开 |
| 连续亏损笔数 | 4 笔 | 冷却 `4 × 一根 K 线周期`，期间只平不开 |

阈值取 8% / 15% 的依据：15% 是 [00](./00-总纲与现状诊断.md) 全局指标表里的最大回撤红线，8% 取其约一半作为提前减速点；连亏 4 笔在胜率 45% 的假设下的自然发生概率约 9%，低到不会频繁误触，高到能在真正失效时及时刹住。

## 五、验收指标与门禁

| 指标 | 阈值 | 采样窗口 | 不达标处置 |
|---|---|---|---|
| 仓位-波动率相关性 | `f` 与 `realized_vol` 的秩相关 < −0.3 | 滚动 100 笔 | 说明目标化未生效，检查 `vol_target` 标定 |
| 被扫损率 | 止损触发后 `horizonBars` 内价格回到原方向的比例 < 40% | 滚动 100 笔 | 上调 `stop_atr_mult` 至 2.0 |
| 有效敞口 | ≤ `effective_exposure_cap` | 实时 | 阻断新开仓 |
| 最大回撤 | < 预算的 15% | 实时 | 刹车必须已在 8% 处减速；若未减速即为刹车失效，阻断上线 |
| 连亏熔断误触率 | 每 200 轮触发 < 3 次 | 滚动 200 轮 | 上调连亏阈值至 5 笔 |
| 平仓永不被拦 | `close` / `cancel_order` 被本篇任何机制拦截的次数 = 0 | 每次提交 | 阻断合并 |

## 六、风险与回滚

**自我反驳一（必须写明）**：**本改动可能反而降低收益。** 波动率目标化在趋势行情中会**主动缩小**仓位——而加密永续最赚钱的行情恰恰是高波动的单边趋势。若实测显示缩仓轮次的事后收益显著高于满仓轮次，说明 `vol_target` 对本策略族过低。监控信号是「按 `f` 分位分箱的事后收益单调性」，若最低仓位分箱的事后收益最高，即判定目标化方向错误，应回退固定占比并改用其他方式控风险。

**自我反驳二**：**四分之一凯利仍可能过激。** 凯利公式对 `p` 的估计误差极其敏感，而 [02](./02-信号层重构与元标签.md) 的先验样本量下限只有 200；若 `p` 高估 5 个百分点，最优仓位会被高估近一倍。缓解：`min()` 里的波动率目标项本身就是一道独立上限，两者取小即使凯利项失真也不会失控；此外「零开仓监控」的对偶——「仓位恒等于 `f_max`」也应当被监控，它意味着凯利项从未生效。

**自我反驳三**：回撤刹车与利润保护棘轮的冷却期（`ai_trade_profit_guard_cooldown_s = 180.0`，`config.py:246`）可能叠加，导致保护性平仓后长时间无法重新入场，错过真实反转。缓解是两层冷却取**并集而非累加**，且刹车只拦开新仓、不影响保护层自身的平仓动作。

**回滚路径**：`sizing_enabled = False` ⇒ 逐字回退 `_compute_sz`；`stop_atr_mult` 置 0 ⇒ 回退固定百分比止损；`effective_exposure_cap` 置极大值 ⇒ 关闭相关性约束；回撤刹车三级阈值各自独立可关。四者互不依赖。上线闸门见 [06](./06-离线评估与上线闸门.md)，实盘度量见 [07](./07-实盘可观测与归因.md)。
