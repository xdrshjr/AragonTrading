# 01 · 交易成本与执行质量

**本篇结论先行**：本篇是全集的第一优先级，因为它修的是**盈亏口径本身**。**改什么**：先做 A0——让实盘已实现盈亏从毛口径变成净额口径（D-16），再建立往返成本模型 `C`（D-1/D-17/D-18/D-2），最后落地最小可交易 edge 门禁。**为什么**：`_close_pnl` 是纯价差乘数量（`services/quant/app/live_auto/executor.py:732-738`）、成交记录写死 `"fee": 0.0`（`executor.py:779`），在这个前提下做的任何胜率先验、参数调优与保护层标定，标签都是被污染的。**验收看什么**：费率入账完整性必须先到 100%，然后才是实测往返成本与成本占比。

## 一、问题定位

**D-16（零费率入账，本篇首要任务）**：`_close_pnl(exit_px)` 只算 `数量 × 价差`（`executor.py:732-738`），`_make_trade` 写死 `"fee": 0.0`（`executor.py:779`），而只读属性 `session_pnl_usd = 已实现 + 未实现`（`executor.py:147-149`）正由它累加。这个值同时被四处消费：会话级金额止盈止损（`services/quant/app/ai_auto/session.py:898-907`）、利润保护棘轮的浮盈判据、统计看板、以及喂进决策 prompt 的「会话盈亏」。结论是**每一笔往返都被系统报得比真实结果好约一个往返成本**，模型在系统性乐观的反馈里学习。

**D-1（成本不进决策）**：全仓库没有 `maker_fee_bps` 这个常量；`default_taker_fee_bps = 5.0` 与 `default_slippage_bps = 2.0`（`services/quant/app/config.py:280-281`）的全部消费方是 `SimBroker`（`services/quant/app/engine/simulator.py:103-109`）、AI 回测（`services/quant/app/ai_auto/backtest.py:248-249`）与纸面/影子路径（`services/quant/app/paper/session.py:60-61`、`ai_auto/signals.py:30-31`）。也就是说 `C ≈ 14 bps` 是回测世界的成本，实盘世界的 C 既没进盈亏，也没进任何门禁。

**D-17（限价与市价成本不可区分）**：限价能力**早已上线且默认开启**——`ai_trade_limit_orders_enabled` 默认 `True`（`config.py:163`），`_do_open` 按是否携带限价发 `limit` 或 `market`（`executor.py:260-263`），挂单状态机在 `live_auto/resting.py`，超时 `ai_trade_limit_order_ttl_s = 300.0`（`config.py:169`）。但状态机只回答「成交了没有」，不产出费率归属；`_inject_explain_meta`（`session.py:248-261`）也不落 `ordType`。因此 maker 到底省了多少钱，目前只能是断言。

**D-18（滑点从未被观测）**：成交记录只有 `price`（`executor.py:778`），没有下单时的期望成交价及其差值，`default_slippage_bps = 2.0` 是模拟侧的假设值且不作用于实盘。成本模型因此无法被实盘数据校准。

## 二、目标与不做什么

**目标**：① 实盘每笔平仓的盈亏含双边费率与实测滑点；② 产出一个可被实盘数据校准的往返成本函数 `C(instId, bar, ordType, holdBars)`；③ 引入最小 edge 门禁，让期望毛收益不足以覆盖 `k_min × C` 的轮次自动降级为 hold。

**不做什么**：① **不新建限价能力**——它已上线，本篇改的是挂价策略、TTL 自适应与费率归属记账；② 不改动交易所侧 OCO 的既有行为；③ 不引入新的第三方 Python 包（资金费率走新增的 OKX 只读端点，`requirements.txt` 不变）；④ 不承诺 maker-first 一定更省——未成交的机会成本必须同时入账。

## 三、方案设计

### 3.1 A0：净额 PnL 口径（P0 级前置，两步走）

**第一步「只记录不切换」**：成交回执里的真实 `fee` 与 `fillPx` 落进 `trade["fee"]` 与 `explain.meta`，`_close_pnl` 的返回值不变。此时看板可同时展示毛/净两条曲线，用于滚动 100 笔的对照。
**第二步「切换判据」**：`_close_pnl` 扣双边费用与实测滑点，`session_pnl_usd` 随之变净额。切换由独立开关 `ai_trade_net_pnl_enabled` 控制，**默认 `False` ⇒ 逐字回退毛口径**（沿用本仓库「总闸默认关即字节级回退」的既有范式）。

### 3.2 往返成本模型

`C = feeOpenBps + feeCloseBps + 2×(halfSpreadBps + impactBps) + fundingCarryBps`

**费率按开/平两腿分别取值**，因为一腿可能是 maker、另一腿可能是 taker——这正是 D-17 说的当前不可区分之处。参数默认值与依据：

| 参数 | 默认值 | 取值依据 |
|---|---|---|
| `taker_fee_bps` | 5.0 | 与既有 `config.py:280` 同源，OKX 永续 taker 档位 |
| `maker_fee_bps` | 2.0 | 新增常量；与 taker 的差额是 maker-first 的全部收益来源，须由实测校准 |
| `half_spread_bps` | 由盘口实测，缺失时回落 1.0 | 无 books5 时的保守假设；取数见 [03](./03-因子层接入AI决策.md) 的微观结构讨论 |
| `impact_bps` | 0.5 | 单笔名义额远小于盘口深度时的保守常数，名义额 > 前五档 20% 时线性放大 |
| `k_min` | 2.0 | 往返成本 14 bps 时要求毛 edge ≥ 28 bps，对应 15m 周期约 0.28% 的目标位距离，可由 ATR 校验 |
| `funding_poll_ttl_s` | 60.0 | 资金费率每 8 小时结算一次，60 秒缓存足够且不构成决策轮内 IO |

**资金费率取数**：仓库当前**没有**该端点——`okx/rest_client.py:226-236` 的唯一公共只读调用是 `/api/v5/public/instruments`。需新增 `GET /api/v5/public/funding-rate` 与 `/funding-rate-history` 的只读方法与会话级缓存，**决策轮内禁止任何网络 IO**。取数失败即整项缺席降级：`fundingCarryBps = None` ⇒ 成本模型标 `confidence = "degraded"` ⇒ edge 门禁自动收紧到 `k_min × 1.2`，**绝不静默按 0 计**。

### 3.3 最小 edge 门禁与其插入位置

判据：`expectedGrossEdgeBps ≥ k_min × totalBps`。期望毛收益由 [02](./02-信号层重构与元标签.md) 的概率化信号给出（`p × 目标位距离 − (1−p) × 止损距离`，均以 bps 计）。

**插入位置（硬约束）**：现有确定性链为铁律（`session.py:571-572`）→ 利润保护冷却（`session.py:574`）→ 共识（`session.py:575`）→ 下单前反思（`session.py:578-579`）→ 执行（`session.py:580`）。edge 门禁必须插在**共识门禁之后、反思之前**，即 `session.py:575` 与 `session.py:578` 之间。理由与 `session.py:568-570` 已确立的先例同构：① 必须落在 `decide` 之后，否则重试循环只认 `_map_decision` 的 degrade，落进去会每轮白烧 LLM；② 必须落在反思之前，被拦轮此时已是 `hold`，而反思对 `hold` 本就直通（`session.py:644-646`）⇒ EV 不足的轮次自动省掉一次反思 LLM 调用，**门禁本身就是省钱项**。回测侧须插在 `backtest.py` 中语义等价的同一位置，否则复现 D-14 的链路不同构。

门禁形态刻意镜像已有的 `signals.apply_consensus_gate`（`signals.py:137`）与 `base_rules.apply_ma_band_gate`（`base_rules.py:193`）：纯函数、显式入参、只会更保守、`close` / `cancel_order` 永不被拦、实盘与回测共用同一核心、默认关闭时逐字回退。

### 3.4 挂价策略与未成交机会成本

maker 腿把费率从 5 bps 降到约 2 bps 并省掉半价差，代价是成交概率小于 1。因此挂价策略的目标函数是 `p_fill × (edge − C_maker) + (1 − p_fill) × (−机会成本)`，其中机会成本 = TTL 内价格朝有利方向走掉的幅度。TTL 自适应建议：默认沿用 300 秒，在实测 `p_fill < 0.5` 的标的/周期上按根收缩至 1 根 K 线周期。**不得只比较费率就宣称限价更省。**

## 五、验收指标与门禁

| 指标 | 阈值 | 采样窗口 | 不达标处置 |
|---|---|---|---|
| 费率入账完整性 | = 100% | 滚动 50 笔 | 阻断：未达标前不得开启 A0 第二步，也不得据任何盈利指标下结论 |
| 实测滑点偏差 | 绝对值 < 3 bps | 滚动 50 笔 | 重估成本模型并把 `k_min` 临时上调至 2.5 |
| 成本模型偏差 | 实测 C 与模型 C 之差 < 5 bps | 滚动 100 笔 | 重新标定 `impact_bps` 与 `half_spread_bps` |
| 限价成交率 `p_fill` | ≥ 0.5 | 滚动 50 次挂单 | 收缩 TTL 至 1 根 K 线；仍不达标则该标的回退 taker |
| 成本占比 | < 35% | 滚动 100 笔 | 触发挂价策略复审 |
| edge 门禁拦截率 | 20%~70% | 滚动 200 轮 | 高于 70% 视为过度收紧（见下节回滚），低于 20% 视为门禁未生效 |

## 六、风险与回滚

**自我反驳一（必须写明）**：**A0 会让盈亏数字变差，用户极可能误判为「系统被改坏了」。** 这不是副作用而是本质——之前的数字是错的。缓解：默认关闭开关、两步走、切换前后各留一份滚动 100 笔的毛/净对照表，并在看板显式标注「历史数据与新口径不可比」。

**自我反驳二**：**本改动可能反而降低收益。** 如果真实 edge 分布的中位数本就接近 `k_min × C`，门禁会把大量微正期望的交易一并拦掉，而这些交易的累积贡献可能为正。监控信号是「被门禁拦下但事后 `horizonBars` 内验证方向正确的比例」，该比例 > 60% 且持续两周即说明 `k_min` 过高，应下调至 1.5 重测。

**自我反驳三**：成本模型的 `impact_bps` 与 `half_spread_bps` 在没有盘口数据时是拍出来的常数；若实测偏差长期超阈，说明模型本身而非参数有问题，应退回到「只用实测费率 + 实测滑点」的两项简化式，而不是继续加项。

**回滚路径**：`ai_trade_net_pnl_enabled = False` 逐字回退毛口径；`k_min = 0` 等价于关闭 edge 门禁；资金费率取数失败已内建缺席降级。三个开关互相独立，可单独回退。上线闸门见 [06](./06-离线评估与上线闸门.md)，实盘度量见 [07](./07-实盘可观测与归因.md)。
