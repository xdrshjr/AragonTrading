# 08 · 实施路线图与里程碑

**本篇结论先行**：**改什么**：把 01~07 的机制切成三个阶段（止血 / 结构 / 进化），规定依赖顺序、每阶段的出口条件与完整的回滚开关清单。**为什么**：这套改进一次性提出了成本模型、先验体系、元标签、因子接入、仓位重构、五道闸门与归因表七大块，若不强制切分，计划必然变成书架文档；而且它们之间存在硬依赖——**A0（净额 PnL 口径）不落地，后面所有阶段的验收都建立在被污染的标签上**。**验收看什么**：每阶段只看两三个出口指标，不达标不进入下一阶段；每个上线项都必须有一个默认关闭的独立开关。

## 一、问题定位

本仓库的工程质量并不差——限价委托状态机（`services/quant/app/config.py:163`、`services/quant/app/live_auto/resting.py`）、利润保护棘轮（`config.py:217-253`、`services/quant/app/ai_auto/profit_guard.py`）、基础策略铁律层（`services/quant/app/ai_auto/base_rules.py`）、下单前二次反思（`config.py:135`）都已合并且默认开启。**问题恰恰在于「每一轮迭代都在加一层保护，却没有一层回答值不值得做」**。

因此路线图的第一条纪律是：**阶段一不加任何新的保护层**，只做两件事——把成本记进账，把不值得做的交易拦掉。第二条纪律是：**每个阶段的产物必须能独立回滚**，因为这个工作树历来同时存在多个在制特性，混合提交的代价很高。

三条依赖关系是硬的，顺序不可交换：

| 依赖 | 原因 |
|---|---|
| A0 → 一切验收指标 | `_close_pnl` 是纯价差（`services/quant/app/live_auto/executor.py:732-738`）、`"fee": 0.0`（`executor.py:779`），口径不修则标签有偏 |
| [01](./01-交易成本与执行质量.md) 成本模型 → [04](./04-决策智能体改造.md) EV 不等式 | 不等式右边就是成本 |
| [02](./02-信号层重构与元标签.md) 先验 → [05](./05-风险与仓位管理.md) 仓位公式 | 凯利项的 `p` 来自先验 |

## 二、目标与不做什么

**目标**：① 用最小改动面在阶段一拿到可判断的结论；② 让每个阶段的出口条件可度量、可证伪；③ 提供一张完整的回滚开关清单，任何一项出问题都能单独关掉。

**不做什么**：① 不并行推进多个阶段——阶段二的任何一项都不得在阶段一出口条件达标前上线；② 不在同一次提交里混入多个特性的改动（本工作树历来有多个在制特性，须按精确路径 `git add`）；③ 不承诺任何阶段的收益率数字，只承诺指标达标或不达标；④ 不在阶段一动 prompt 之外的模型行为。

## 六、风险与回滚

**自我反驳一（必须写明）**：**本计划整体可能反而降低收益。** 它的核心假设是「亏损来自负期望而非运气」。若阶段一结束时滚动 100 笔的净期望在统计上与 0 无法区分（`tStat` 绝对值 < 1.0），真正的结论是**样本量不足以支持任何改造决策**，此时继续推进阶段二只是在噪声上做工程。缓解：M1 的出口条件里必须同时包含「样本量 ≥ 100 笔」，未达样本量则延长阶段一的观察期，而不是提前进入阶段二。

**自我反驳二**：**分阶段本身有代价。** 阶段一只上成本门禁而不上先验，意味着 edge 的分子（期望毛收益）此时只能由模型自报或用简化规则估算，精度很差——这可能让阶段一的门禁表现劣于「先验 + 门禁」同时上线的情形，从而给出一个悲观的错误结论。缓解：阶段一的 edge 估算必须显式标注为「粗估」，M1 的判据只看转化率与入账完整性这两条**结构性**指标，**不看净期望**；净期望的判据留到 M2。

**自我反驳三**：十二个新模块、约 1720 行新代码在一个已有多个在制特性的工作树上落地，冲突与误提交的风险是真实的。缓解是每阶段独立分支 + 精确路径暂存 + 每个开关默认关闭（即便误合并也不改变运行时行为）。

**总回滚**：把上表十个开关全部置为关闭值，系统逐字节回退到本计划之前的行为，无残留状态、无数据库变更（全部机制零新表、零迁移）。总纲与全局指标见 [00](./00-总纲与现状诊断.md)。
