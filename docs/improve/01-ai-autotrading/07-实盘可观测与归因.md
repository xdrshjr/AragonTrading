# 07 · 实盘可观测与归因

**本篇结论先行**：**改什么**：给每一笔往返交易补一条归因记录，把「信号偏差 / 决策偏差 / 执行偏差 / 成本偏差」四类误差分开度量，并据此做自动降级与日/周复盘。**为什么**：现在的会话统计 `_compute_ai_stats`（`services/quant/app/ai_auto/session.py:1357-1404`）只有动作计数、观望占比、平均置信度、降级数与四个反思计数，**没有净期望、没有 t 值、没有成本占比**（D-15），因此「亏损是运气还是负期望」这个最基本的问题无法回答。**验收看什么**：归因记录覆盖率、四类偏差是否各自在阈内、以及自动降级是否在阈值被突破时真的触发。

**显式前置条件**：本篇的核心字段 `realizedEdgeBps` 只有在 [01](./01-交易成本与执行质量.md) 的 A0（净额 PnL 口径）落地之后才有意义——在 `"fee": 0.0`（`services/quant/app/live_auto/executor.py:779`）的现状下，它恒等于毛 edge。**A0 未落地则本篇的成本偏差一栏必须显示「不可用」，不得填 0。**

## 一、问题定位

**D-15（统计口径缺显著性与净期望）**：`_compute_ai_stats` 的返回体是 `decisionRounds / actionCounts / holdRate / avgConfidence / degradedRounds` 加四个反思计数（`session.py:1394-1404`）。这些是**过程指标**，回答的是「系统做了什么」，而不是「做得对不对、值不值」。缺了净期望与显著性，任何改进都只能靠感觉判断。

**D-18（滑点从未被观测）**：成交记录只有 `price`（`executor.py:778`），没有下单时的期望成交价，因此实测滑点是一个**从未被测量过的量**；`default_slippage_bps = 2.0`（`services/quant/app/config.py:281`）是模拟侧假设值且不作用于实盘。

**D-17（限价与市价不可区分）**：`_inject_explain_meta`（`session.py:248-261`）当前落的是 `source / instId / bar / barTs / clOrdId / ordId`，**没有 `ordType`**。因此即便限价能力默认开启（`config.py:163`），也无法在事后区分哪些成交走了 maker 腿。

**一个结构性优势必须先认账**：`_inject_explain_meta` 是本仓库 explain 元数据的**唯一注入收口**。这意味着归因记录可以零新表、零迁移地挂进去——本篇因此不需要任何数据库变更。

## 二、目标与不做什么

**目标**：① 每笔往返产出一条结构化归因记录，落在既有 `trade.explain.meta.attribution` 子对象；② 把误差拆成四类分别归因，让「该改哪一层」有据可依；③ 任一类偏差超阈时自动降级为只平不开，而不是等会话级绝对金额阈值兜底。

**不做什么**：① **不新建数据库表**——沿用唯一收口 `_inject_explain_meta`，只加字段不加收口；② 不在决策轮内做聚合统计（决策轮内禁止任何 DB IO），聚合走既有历史统计端点按需计算；③ 不改动既有 `_compute_ai_stats` 已有键的语义（加法写，向后兼容）；④ 不做实时告警推送，本阶段只做看板与日/周报表。

## 三、方案设计

### 3.1 归因记录的字段与四类偏差

> 提案（proposal）· 未实现

```text
TradeAttribution = {signalIds, priorWinRate, expectedEdgeBps, realizedEdgeBps,
                    feeBps, slipBps, fundingBps, decisionLatencyMs, gatePath}
# 挂在 trade.explain.meta.attribution；gatePath 记录本轮依次经过的门禁与各自裁决
```

| 偏差类型 | 定义 | 主要字段 | 归属文档 |
|---|---|---|---|
| 信号偏差 | 先验胜率 − 实际胜率 | `priorWinRate` vs 实际结果 | [02](./02-信号层重构与元标签.md) |
| 决策偏差 | 模型自估 edge − 门禁计算 edge | `expectedEdgeBps` vs 门禁值 | [04](./04-决策智能体改造.md) |
| 执行偏差 | 期望成交价 − 实际成交价 | `slipBps`、`decisionLatencyMs` | [01](./01-交易成本与执行质量.md) |
| 成本偏差 | 模型成本 − 实测成本 | `feeBps + slipBps + fundingBps` vs `CostBreakdown.totalBps` | [01](./01-交易成本与执行质量.md) |

**四类分开度量的价值**：若净期望为负而四类偏差都在阈内，说明问题在 edge 本身（该回到 02/03 找信号）；若信号偏差在阈内而执行偏差超阈，说明信号是好的、执行在漏钱（该回到 01 改挂价策略）。这正是「该改哪一层」的判据。

### 3.2 需要新增的元数据字段

在 `_inject_explain_meta` 的既有收口上追加：`ordType`（区分 maker/taker 腿）、`expectedFillPx`（下单时的期望成交价）、`slippageBps`（二者之差）、`attribution`（上述子对象）。全部 `setdefault` 写入，与既有六个键同范式，**不改任何既有键的语义**。

### 3.3 显著性与净期望统计（补 D-15）

在既有 `aiStats` 上加法写四个新键：

| 新键 | 定义 | 默认展示条件 |
|---|---|---|
| `netExpectancyUsd` | 滚动 100 笔的净盈亏均值 | A0 已落地才展示，否则显示「不可用」 |
| `tStat` | `均值 / (标准差 / √n)` | `n ≥ 30` 才输出，否则 `null` |
| `costRatio` | `Σ成本 / Σ毛盈亏绝对值` | 同上 |
| `fillRateLimit` | 限价挂单成交率 | 有挂单样本才输出 |

`n ≥ 30` 的门槛与 [06](./06-离线评估与上线闸门.md) 的 `min_test_trades = 30` 同源，也与仓库既有的样本量底线思路一致（`MIN_IC_SEGMENTS = 6`，`services/quant/app/engine/factors/evaluation.py:21`）。**样本不足时输出 `null` 而非 0**，沿用「键缺失即整段省略」的既有范式。

### 3.4 自动降级

| 触发条件 | 默认阈值 | 动作 |
|---|---|---|
| 成本偏差 | 实测 − 模型 > 5 bps，滚动 50 笔 | `k_min` 自动上调 20%，并发一条轨迹留痕 |
| 执行偏差 | 实测滑点 > 3 bps，滚动 50 笔 | 该标的挂价策略回退 taker，TTL 收缩至 1 根 |
| 净期望 | < 0 且 `tStat < −1.5`，滚动 100 笔 | **降级为只平不开**，等待人工复核 |
| 归因覆盖率 | < 95%，滚动 100 笔 | 不降级，但阻断任何基于归因的参数调整 |

`tStat < −1.5` 的依据：单尾 93% 置信度附近，比 −2.0 更早介入（亏损场景下宁可早停），又不至于被随机波动频繁触发。

### 3.5 日/周复盘报表

日报：当日往返笔数、净期望、四类偏差、门禁拦截分布（`gatePath` 聚合）、降级触发记录。周报追加：回测-实盘漂移（同期动作分布的 JS 散度，阈值 0.15）、champion-challenger 对照、先验陈旧度清单。报表由既有历史统计端点聚合产出，**零新表**。

## 四、与现有代码的接入点

**现状已有什么**：`_inject_explain_meta` 这个**唯一的** explain 注入收口（`session.py:248-261`，已落 `source / instId / bar / barTs / clOrdId / ordId`）、`_compute_ai_stats` 的会话统计（`session.py:1357-1404`）、AI 自动交易的持久化统计看板与只读历史端点、执行轨迹回放（分阶段 trace）、`session_pnl_usd` 的只读聚合（`executor.py:147-149`）。**注入点与看板都已存在，本篇是加字段，不是加管道。**

## 五、验收指标与门禁

| 指标 | 阈值 | 采样窗口 | 不达标处置 |
|---|---|---|---|
| 归因覆盖率 | ≥ 95% 的平仓笔有完整 `attribution` | 滚动 100 笔 | 阻断基于归因的一切参数调整 |
| 费率入账完整性 | = 100% | 滚动 50 笔 | 成本偏差一栏显示「不可用」，不得填 0 |
| 成本偏差 | 绝对值 < 5 bps | 滚动 100 笔 | 自动上调 `k_min` 20% |
| 执行偏差 | 实测滑点 < 3 bps | 滚动 50 笔 | 回退 taker 并收缩 TTL |
| 信号偏差 | 先验胜率与实际胜率之差 < 10 个百分点 | 滚动 100 笔 | 触发 [02](./02-信号层重构与元标签.md) 的先验重算 |
| 决策偏差 | 模型自估与门禁计算 edge 差异 < 15 bps 的占比 ≥ 60% | 滚动 200 轮 | 触发 [04](./04-决策智能体改造.md) 的 prompt 复审 |
| 回测-实盘漂移 | JS 散度 < 0.15 | 每周 | 暂停参数变更，回到 [06](./06-离线评估与上线闸门.md) |

## 六、风险与回滚

**自我反驳一（必须写明）**：**本改动可能反而降低收益。** 自动降级是一把双刃刀——`tStat < −1.5` 在滚动 100 笔上的误触概率并不低（正期望系统也会有连续不利的窗口），一次误触意味着整段行情空仓，机会成本可能大于它避免的亏损。缓解：降级只作用于「开新仓」，平仓与保护层动作不受影响；降级后须有明确的解除条件（人工复核 + 后续 50 笔净期望回正），而不是永久停摆；监控信号是「降级期间若继续交易的假设收益」，若长期为正说明阈值过严。

**自我反驳二**：**归因记录会让 explain 体积显著增长。** `attribution` 有九个字段，叠加新增的 `ordType / expectedFillPx / slippageBps`，每笔成交的 explain 体积可能翻倍。若历史统计端点的聚合因此变慢，正确动作是把 `gatePath` 压成短码而非删字段——门禁路径是「该改哪一层」判据的核心输入。

**自我反驳三**：四类偏差的划分假设了误差可以线性分解，但实际上它们互相耦合——执行偏差大会让实际胜率下降，从而被误记为信号偏差。因此四类偏差应当被当作**定位线索**而非精确分解，任何基于单一偏差的自动动作都必须保守（本篇只让成本偏差与执行偏差触发自动动作，信号偏差与决策偏差只触发人工复审）。

**回滚路径**：`attribution_enabled = False` ⇒ 不写 `attribution` 子对象，`_inject_explain_meta` 逐字回退当前六键；`auto_degrade_enabled = False` ⇒ 关闭全部自动降级，回到仅有会话级绝对金额阈值的现状（`session.py:898-907`）。两者独立。落地节奏见 [08](./08-实施路线图与里程碑.md)。
