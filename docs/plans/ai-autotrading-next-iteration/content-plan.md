## 三、核心命题（全集的骨架，五篇都围绕它展开）

> **上一轮解决的是「有没有机制」，这一轮要解决的是「机制在什么周期上、按什么阈值生效，以及那个阈值是谁定的」。**

四条经回读源码逐条复核的事实，构成本轮全部提案的地基。**第 1 条是本轮最重要的纠偏，写作时必须原样守住它的方向**：

1. **闸门不是没开，是开着且几乎否决一切——而阈值从未标定。** 出厂默认值确实全是无效值，但那不是实盘跑的东西：`config.py:538` 的 `ai_trade_discipline_enabled = True`（**默认开**）与 `config.py:539-540` 的 `ai_trade_discipline_default_preset = "balanced"` 让每一个从 API 层启动的会话都套上一份**会话私有的 Settings 副本**；`config.py:533-535` 逐字写明「那一整排 `ai_trade_*` 阈值的既有默认值本轮一个都没动……改变的只有一件事：从 API 层启动的会话会默认套上一份预设副本」。`discipline.py:66-83` 的 `balanced` 把 `edge_gate_k_min` 置 `1.5`、`min_consensus` 置 `1`、`min_confidence` 置 `0.50`、`sizing_enabled` 置 `True`、`effective_exposure_cap_mult` 置 `2.0`、`stop_atr_mult` 置 `2.0`、三档刹车全部置为非零；`AiTradeLaunchModal.tsx:598-600` 在实盘与回测两条路径上都下发 `discipline: { preset }`。而 `discipline.py:36` 对这张冻结表的自评是：「**这些数字没有经过回测校准**」。**写作硬约束**：不得写「闸门空转 / 机制是暗的 / 用户跑的链路与文档不是同一条」——那是 `config.py:533-535` 明文警告的误读；只能写「出厂默认值与会话生效值是两套数，生效的那套没有标定依据」。
2. **真正压垮盈利的是周期与标的的可交易性，这一条已有实测记录。** `discipline_view.py:108-111` 记录：同一批 BTC 1m K 线上，**最宽松**的 `aggressive`（k=1.0）仍有 **93.0%** 的否决率，且明写「放宽 k 只能把曲线整体平移一点……真正的补救是**换时间级别**」；`config.py:542-543` 记录：实测 BTC 1m 上 **62.3%** 的 2×ATR 止损比一笔市价往返成本还窄——源码原话是「**一台结构性手续费机器**」。**在单笔波动幅度覆盖不了往返成本的周期上，任何门禁调参都只是在选择亏多亏少。**
3. **系统的历史读数已经解释了亏损，且解释是算术性的。** `ai_auto/track_record.py:3-5` 记录：模型历史胜率约 40%、赔率约 1.01，而 40% 的胜率要求赔率 1.47 才能打平。**这不是运气问题，是每笔交易的盈亏比系统性不足。**
4. **用来标定闸门的样本，其口径本身还没干净。** `ai_auto/profitability.py:18-20` 记录：实测 193 笔往返里 172 笔（89.1%）的腿费恒 0，且「那是『没记』不是『免费』」；`profitability.py:3-4` 记录：28 个分组里 10 组零成交。**在这样的样本上把 `k_min` 从 1.5 调到 2.0，调出来的数不可证伪。**

由此推出本轮的四条主线，与 01~04 号一一对应：

- **主线一 · 补证据**（01 号）：让 edge 的分子与成本的分母都来自真实观测，而不是常数回落值。
- **主线二 · 标定既有阈值、并按序验证**（02 号）：既有的四档预设**已经在跑**，缺的是三件东西——每个阈值的实测标定依据、单变量的调整顺序与观察窗口、自动回滚判据。**本主线不新建档位体系，只在 `ai_auto/discipline.py` 的冻结表之上补标定与编排。**
- **主线三 · 建验证闭环**（03 号）：让「动一个预设阈值」这件事必须先过一份可复现的闸门报告。
- **主线四 · 产品化与还债**（04 号）：把「为什么没开仓 / 这个周期能不能做」做成第一屏的答案，让既有档位的阈值可解释；同时清偿 AI 主链路上 9 个超行数红线文件的技术债。
